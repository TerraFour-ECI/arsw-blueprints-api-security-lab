\section{Objective}
% ─────────────────────────────────────────────────────────────────────────────

This laboratory extends the Blueprints REST API developed in Laboratory~4 by
incorporating a stateless security layer based on \textbf{JSON Web Tokens (JWT)}
following the \textit{OAuth 2.0 Resource Server} pattern.

\begin{conceptbox}[title={Security Objectives}]
\begin{enumerate}
  \item Configure Spring Security 6 as an OAuth2 Resource Server validating
        RS256-signed JWTs.
  \item Implement an in-process token issuer (\texttt{/auth/login}) that
        generates short-lived tokens with fine-grained \textbf{scopes}.
  \item Enforce \textbf{method-level access control} via
        \texttt{@PreAuthorize} distinguishing read (\texttt{blueprints.read})
        from write (\texttt{blueprints.write}) operations.
  \item Expose validated JWT authentication through the \textbf{Swagger UI}
        (OpenAPI 3 Bearer scheme).
  \item Maintain the existing filter pipeline (Identity, Redundancy,
        Undersampling strategies) from the previous lab.
  \item Achieve \textbf{full test coverage} with MockMvc JWT mocks and a
        real end-to-end authentication flow test.
\end{enumerate}
\end{conceptbox}

\section{Application Architecture}
% ─────────────────────────────────────────────────────────────────────────────

The application follows a layered architecture that adds a dedicated
\textbf{Security Layer} on top of the REST layer introduced in Lab~4.

\subsection{Package Structure}

\begin{center}
\small
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{Package} & \textbf{Responsibility} \\
\midrule
\texttt{model}       & Domain entities (\texttt{Blueprint}, \texttt{Point}) \\
\texttt{persistence} & Storage interface + in-memory impl \\
\texttt{filters}     & Strategy pattern filter pipeline \\
\texttt{services}    & Business orchestration \\
\texttt{api}         & REST controllers + DTOs \\
\texttt{auth}        & Token-issuing \texttt{AuthController} \\
\texttt{security}    & Security config, JWT beans, user service \\
\texttt{config}      & OpenAPI / Swagger configuration \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Request / Response Flow}

Every secured request traverses the following layers:

\begin{enumerate}
  \item \textbf{SecurityFilterChain} — Spring Security intercepts the HTTP
        request. Public paths (\texttt{/auth/login}, Swagger) are permitted;
        all \texttt{/api/**} paths require a valid Bearer token.
  \item \textbf{JwtDecoder} — validates the RSA-2048 signature and
        expiration of the incoming JWT.
  \item \textbf{@PreAuthorize} — \texttt{MethodSecurityConfig} evaluates the
        scope claim; insufficient scope yields HTTP~403.
  \item \textbf{Service layer} — business logic and filter application.
  \item \textbf{Persistence layer} — \texttt{ConcurrentHashMap} storage.
  \item \textbf{ApiResponse\textless{}T\textgreater{}} — uniform JSON
        envelope returned to the client.
\end{enumerate}

\begin{warningbox}
The API does \emph{not} rely on an external authorisation server. The same
Spring Boot process generates the RSA key pair at startup, issues JWTs via
\texttt{/auth/login}, and validates them via \texttt{JwtDecoder}.
All key material is ephemeral (in-memory only).
\end{warningbox}

\section{Part 2 --- JWT Security Implementation}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{RSA Key Generation}

\texttt{JwtKeyProvider} generates a 2048-bit RSA key pair at application
startup using the Java Security API:

\begin{lstlisting}[style=javacode, caption={JwtKeyProvider key generation}]
@Component
public class JwtKeyProvider {
    private final RSAPublicKey  publicKey;
    private final RSAPrivateKey privateKey;

    public JwtKeyProvider() throws NoSuchAlgorithmException {
        KeyPairGenerator gen =
            KeyPairGenerator.getInstance("RSA");
        gen.initialize(2048);
        KeyPair pair = gen.generateKeyPair();
        this.publicKey  = (RSAPublicKey)  pair.getPublic();
        this.privateKey = (RSAPrivateKey) pair.getPrivate();
    }
}
\end{lstlisting}

\begin{note}
The key pair is recreated on every restart. All previously issued tokens
become immediately invalid after a restart, which is acceptable for a
development / lab environment.
\end{note}

\subsection{Security Configuration}

\texttt{SecurityConfig} defines the Spring Security filter chain and the
JWT infrastructure beans:

\begin{lstlisting}[style=javacode, caption={SecurityConfig (simplified)}]
@Bean
public SecurityFilterChain filterChain(
        HttpSecurity http) throws Exception {
    http
      .csrf(AbstractHttpConfigurer::disable)
      .sessionManagement(sm -> sm.sessionCreationPolicy(
          SessionCreationPolicy.STATELESS))
      .authorizeHttpRequests(auth -> auth
          .requestMatchers("/auth/login",
              "/swagger-ui/**", "/v3/api-docs/**",
              "/actuator/**").permitAll()
          .anyRequest().authenticated())
      .oauth2ResourceServer(rs ->
          rs.jwt(Customizer.withDefaults()));
    return http.build();
}

@Bean
public JwtDecoder jwtDecoder(JwtKeyProvider keys) {
    return NimbusJwtDecoder
        .withPublicKey(keys.getPublicKey()).build();
}

@Bean
public JwtEncoder jwtEncoder(JwtKeyProvider keys) {
    JWK jwk = new RSAKey.Builder(keys.getPublicKey())
        .privateKey(keys.getPrivateKey()).build();
    return new NimbusJwtEncoder(
        new ImmutableJWKSet<>(new JWKSet(jwk)));
}
\end{lstlisting}

\subsection{Token Issuer — AuthController}

\texttt{POST /auth/login} validates credentials and returns a signed JWT:

\begin{lstlisting}[style=javacode, caption={AuthController token issuance}]
@PostMapping("/auth/login")
public ResponseEntity<TokenResponse> login(
        @RequestBody LoginRequest req) {
    // 1. Load user and verify BCrypt password
    // 2. Build JWT claims
    JwtClaimsSet claims = JwtClaimsSet.builder()
        .issuer("blueprints-api")
        .subject(user.getUsername())
        .issuedAt(now)
        .expiresAt(now.plusSeconds(3600))
        .claim("scope",
            "blueprints.read blueprints.write")
        .build();
    // 3. Sign and return
    return ResponseEntity.ok(new TokenResponse(
        jwtEncoder.encode(...).getTokenValue(),
        "Bearer", 3600));
}
\end{lstlisting}

\section{Part 4 --- OpenAPI / Swagger with JWT}

\subsection{OpenAPI Security Scheme}

\texttt{OpenApiConfig} registers a \textit{Bearer} security scheme so that
Swagger UI can attach the JWT to every request:

\begin{lstlisting}[style=javacode, caption={OpenApiConfig Bearer scheme}]
@Bean
public OpenAPI customOpenAPI() {
    return new OpenAPI()
      .info(new Info()
          .title("Blueprints API Security")
          .version("2.0.0")
          .description(
              "JWT-secured REST API (RS256)"))
      .addSecurityItem(new SecurityRequirement()
          .addList("bearerAuth"))
      .components(new Components()
          .addSecuritySchemes("bearerAuth",
              new SecurityScheme()
                  .type(SecurityScheme.Type.HTTP)
                  .scheme("bearer")
                  .bearerFormat("JWT")));
}
\end{lstlisting}

\subsection{Endpoint Annotations}

Every controller method is annotated with:

  \item \texttt{@Operation(summary=...)} — human-readable description.

  \item \texttt{@SecurityRequirement(name="bearerAuth")} — tells Swagger to
        add the \texttt{Authorization: Bearer} header.
  \item \texttt{@Tag(name="Blueprints")} — groups endpoints in the UI.

\section{Part 5 --- Filter Pipeline}
% ─────────────────────────────────────────────────────────────────────────────

The filter pipeline from Lab~4 was retained without modification. It
implements the \textbf{Strategy design pattern} to post-process blueprint
point lists:

\begin{lstlisting}[style=javacode, caption={BlueprintsFilter interface}]
public interface BlueprintsFilter {
    Blueprint filter(Blueprint bp);
}
\end{lstlisting}

\subsection{Available Strategies}

\begin{center}
\small
\begin{tabular}{@{}p{2.2cm}p{4cm}@{}}
\toprule
\textbf{Filter} & \textbf{Behaviour} \\
\midrule
\texttt{IdentityFilter}     & Returns the original point list unchanged (default profile). \\
\texttt{RedundancyFilter}   & Removes consecutive duplicate points (\texttt{@Profile("redundancy")}). \\
\texttt{UndersamplingFilter}& Keeps every other point to reduce resolution (\texttt{@Profile("undersampling")}). \\
\bottomrule
\end{tabular}
\end{center}

\subsection{Profile Activation}

The active filter is selected via Spring profiles in
\texttt{application.yml}:

\begin{lstlisting}[style=yamlcode, caption={Profile activation in application.yml}]
spring:
  profiles:
    active: default   # use 'redundancy' or
                      # 'undersampling' to switch
\end{lstlisting}

\begin{note}
\texttt{IdentityFilter} uses \texttt{@Profile("\{!redundancy \&
!undersampling\}")} so it engages automatically whenever neither alternative
profile is active.
\end{note}

\section{Conclusions}
% ─────────────────────────────────────────────────────────────────────────────

\begin{resultbox}[title={Key Findings}]
\begin{enumerate}
  \item \textbf{Stateless security} via JWT eliminates server-side session
        state, making the API horizontally scalable with no shared session
        store.
  \item \textbf{RS256 signing} with an ephemeral RSA key pair ensures that
        tokens cannot be forged, even without a dedicated key-management
        service.
  \item \textbf{Scope-based access control} is more expressive than simple
        role-based control: the same user account can hold both
        \texttt{blueprints.read} and \texttt{blueprints.write}, or only
        the read scope, without requiring multiple user records.
  \item \textbf{\texttt{@PreAuthorize}} at the method level is the
        correct Spring Security 6 approach, keeping security declarations
        co-located with business logic rather than scattered across a
        central configuration.
  \item \textbf{MockMvc JWT mocks} (\texttt{SecurityMockMvcRequestPostProcessors.jwt()})
        allow fast, deterministic unit testing of access-control rules
        without spinning up an authorisation server.
  \item \textbf{Separation of concerns} is preserved: the security layer
        adds zero coupling to the domain, persistence, or filter layers,
        as evidenced by unmodified service and persistence tests.
\end{enumerate}
\end{resultbox}

\subsection{Lessons Learned}

\begin{itemize}
  \item \texttt{GlobalExceptionHandler} must re-throw
        \texttt{AccessDeniedException} and \texttt{AuthenticationException}
        so that Spring Security's \texttt{ExceptionTranslationFilter} can
        convert them to 403/401 responses. Catching them inside
        \texttt{@RestControllerAdvice} produces incorrect 500 responses.
  \item Removing the external \texttt{jwk-set-uri} and relying on the
        locally configured \texttt{JwtDecoder} bean avoids startup failures
        caused by unavailable remote JWKS endpoints during development.
  \item Spring Security auto-configures an \texttt{oauth2ResourceServer}
        only when a \texttt{JwtDecoder} bean is present; explicitly declaring
        \texttt{.oauth2ResourceServer(rs -> rs.jwt(...))} in the filter chain
        definition avoids ambiguity with the auto-configuration.
\end{itemize}
